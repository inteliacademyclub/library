# Stack e Ferramentas do Case Ambev

O TAPI pede uma solução em Python, com API (FastAPI) e interface (Streamlit), mas **não obriga nenhuma biblioteca**: a escolha precisa ser justificada no README. Esta página traz uma combinação **testada em conjunto**, com o link da documentação oficial de cada ferramenta, e as mudanças recentes que podem quebrar o código se você seguir um tutorial antigo.

:::info[Testado em 03/11/2026]
As versões abaixo seguem o guia da trilha (Python 3.12) e foram instaladas juntas. Todos os trechos de código dos materiais da Ambev rodaram com elas, com as mesmas saídas mostradas nas aulas. **Fixe as versões** no `pyproject.toml` e cite-as no README: é parte da reprodutibilidade que o TAPI exige.
:::

## Ambiente completo

```bash
uv init occasion-intelligence --python 3.12 && cd occasion-intelligence

# dados
uv add pandas==3.0.6 numpy==2.5.3 pyarrow==25.0.1 duckdb==1.5.5 pandera==0.33.1 httpx==0.28.1

# território
uv add geopandas==1.2.0 shapely==2.2.0 pyproj==3.8.0 geobr

# modelo
uv add scikit-learn==1.9.1 scipy==1.18.1

# aplicação e testes
uv add fastapi==0.162.0 uvicorn==0.54.0 pydantic==2.13.5 streamlit==1.66.1 pydeck==0.9.3
uv add --dev pytest==9.2.0
```

O `geobr` está sem versão fixada porque não fez parte do teste conjunto: fixe a que for instalada no seu ambiente.

## Como justificar a stack no README

- **Uma linha por ferramenta:** o que ela faz no projeto e por que essa e não outra. Por exemplo: "DuckDB para o ASOF join, porque junta clima e calendário por instante sem trazer o futuro".
- **Versões fixadas** no `uv.lock`, com a versão do Python.
- **O que ficou de fora e por quê.** Por exemplo: "não usamos LLM no MVP porque a justificativa vem do Decision Engine".
