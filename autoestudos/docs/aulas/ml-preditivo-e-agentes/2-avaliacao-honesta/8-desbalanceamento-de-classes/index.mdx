Fraude, cancelamento, falha de equipamento, uma ocasião de consumo específica: muitos alvos de interesse são raros. Com 3% de positivos, o primeiro instinto é "meus dados estão desbalanceados, preciso balancear". Esse instinto costuma levar a mudanças que **não melhoram o modelo** e **estragam as probabilidades**. Esta aula mostra o que de fato muda.

:::info[Ideia central]
Desbalanceamento é um problema de **como medir** e de **onde cortar o score**, antes de ser um problema de treino. Muitas vezes o modelo já ordena bem; o que precisa mudar é a métrica e o limiar.
:::

---

## A armadilha da acurácia

Se 96,8% dos exemplos são negativos, um "modelo" que **sempre responde não** tem 96,8% de acurácia, e nenhuma utilidade. A acurácia premia a classe majoritária. Com classe rara, use **PR-AUC**, **recall em uma precisão mínima** ou **custo esperado** (veja [Métricas de classificação](/aulas/ml-preditivo-e-agentes/avaliacao-honesta/metricas-de-classificacao-e-custo-dos-erros)).

## O que `class_weight` realmente faz

O trecho abaixo compara um modelo sem tratamento e outro com `class_weight="balanced"`, em dados **sintéticos** com cerca de 3% de positivos.

```python
import numpy as np
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, average_precision_score, recall_score, precision_score
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(2)
n = 40_000
X = rng.normal(size=(n, 5))
p = 1 / (1 + np.exp(-(-5.0 + 1.6 * X[:, 0] + 1.2 * X[:, 1])))      # ~1% de positivos (sintético)
y = (rng.random(n) < p).astype(int)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, shuffle=False)
print("positivos no teste:", round(y_te.mean(), 4))

# 1) O "modelo" que nunca prevê a classe rara.
print("acurácia de prever sempre 0:", round(accuracy_score(y_te, np.zeros_like(y_te)), 4))

def avalia(nome, modelo):
    s = modelo.fit(X_tr, y_tr).predict_proba(X_te)[:, 1]
    pr = average_precision_score(y_te, s)
    # limiar escolhido para recall de 60% (ilustrativo), medindo a precisão que sobra
    alvo = np.quantile(s[y_te == 1], 0.4)
    pred = s >= alvo
    print(f"{nome:28s} PR-AUC {pr:.3f} | em recall≈{recall_score(y_te, pred):.2f}: precisão {precision_score(y_te, pred):.3f}")
    return s

s_sem = avalia("sem tratamento", LogisticRegression(max_iter=1000))
s_peso = avalia("class_weight='balanced'", LogisticRegression(max_iter=1000, class_weight="balanced"))
print("PR-AUC igual?", abs(average_precision_score(y_te, s_sem) - average_precision_score(y_te, s_peso)) < 0.02)
print("prob. média prevista (sem / com peso):", round(s_sem.mean(), 3), "/", round(s_peso.mean(), 3))
assert s_peso.mean() > 5 * s_sem.mean()   # o peso distorce a probabilidade
```

A saída obtida com a semente do exemplo:

```text
positivos no teste: 0.0319
acurácia de prever sempre 0: 0.9681
sem tratamento               PR-AUC 0.354 | em recall≈0.60: precisão 0.227
class_weight='balanced'      PR-AUC 0.354 | em recall≈0.60: precisão 0.226
PR-AUC igual? True
prob. média prevista (sem / com peso): 0.031 / 0.265
```

Três conclusões:

1. **A acurácia de 96,8% é um modelo inútil.** É o piso que qualquer modelo precisa superar de verdade.
2. **O ranking não melhorou.** A PR-AUC é idêntica (0,354), e a precisão num mesmo nível de recall também. O peso não ensinou nada novo ao modelo.
3. **A probabilidade piorou.** A média prevista com peso é 0,265, enquanto a prevalência real é 0,032: o modelo agora "acha" que há 27% de positivos. O score deixou de ser uma probabilidade. Se alguém ler "0,40" como "40% de chance", vai errar por uma ordem de grandeza.

Isso não torna `class_weight` inútil: em modelos mais flexíveis ou com poucos positivos, ele pode ajudar o ajuste. Mas o ganho precisa ser **medido** (PR-AUC e recall em precisão mínima), e o score resultante **precisa ser recalibrado** se for lido como probabilidade (veja [Calibração de probabilidade](/aulas/ml-preditivo-e-agentes/incerteza-e-explicabilidade/calibracao-de-probabilidade)).

## As opções, uma a uma

| Opção | O que faz | Cuidado |
| :--- | :--- | :--- |
| **Mudar a métrica** | Mede PR-AUC, recall e custo em vez de acurácia | Custo zero, e quase sempre o primeiro passo |
| **Mudar o limiar** | Corta o score onde o custo é mínimo | Escolha na validação |
| **`class_weight` / pesos** | Penaliza mais o erro na classe rara | Distorce a probabilidade; recalibre |
| **Subamostragem** | Descarta negativos | Perde informação; só no treino |
| **Sobreamostragem** (duplicar ou sintetizar positivos) | Aumenta os positivos | Risco de superajuste e de vazamento se duplicar antes de dividir |
| **Mais dados da classe rara** | Coleta ou rotula mais positivos | Costuma ser o que mais ajuda, e o mais caro |

Regras de ouro:

- **Reamostre só o treino.** O teste e a validação mantêm a prevalência real, senão as métricas deixam de refletir o uso.
- **Duplique depois de dividir.** Duplicar positivos antes da divisão coloca cópias do mesmo exemplo no treino e no teste: é vazamento.
- **Divida em ordem temporal** quando houver tempo, mesmo com classes raras. Estratificar ajuda a ter positivos em todos os conjuntos, mas não substitui o corte temporal.

## Erros comuns

:::warning[Armadilhas de desbalanceamento]
1. **Reportar acurácia.** O modelo "sempre não" vence.
2. **Reamostrar antes de dividir.** Cópias do mesmo exemplo vazam entre treino e teste.
3. **Reamostrar o teste.** A métrica deixa de refletir a prevalência real.
4. **Usar pesos e ler o score como probabilidade.** A probabilidade fica inflada.
5. **Assumir que balancear sempre ajuda.** Meça com PR-AUC antes e depois.
:::

## Resumo

- **Acurácia engana** com classe rara: use PR-AUC, recall e custo.
- **`class_weight` não melhora o ranking** por si só, e **distorce as probabilidades**.
- O **limiar** escolhido pelo custo resolve muito do problema.
- **Reamostre só o treino**, e duplique **depois** de dividir.
- Se o score for lido como probabilidade, **recalibre**.
